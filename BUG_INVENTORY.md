## A. Root-cause cluster: Mongo→Postgres shape mismatch (applicant flow) — 🟢 FIXED IN TREE (uncommitted)

One missing serializer caused every applicant-side symptom the user reported. The frontend expects the legacy Mongo shape (camelCase + nested `contactInfo`); Postgres returns flat snake_case. Fix = new `serializeApplicant()` + `contactInfo`-aware write handlers.

| # | Symptom | Root cause | Location | Sev | Status |
|---|---------|-----------|----------|-----|--------|
| A1 | Pending user missing from "Registered applicants" | list filtered `status='registered'` only | `applicant.controller.js` `getRegisteredApplicants` | P1 | 🟢 |
| A2 | Applicant card → "doesn't exist" / name `undefined` | raw snake_case rows returned; UI reads `contactInfo.name` | `getApplicantById/ByKey` | P0 | 🟢 |
| A3 | Admin edit → Save does nothing | `updateApplicant` ignored nested `contactInfo` | `updateApplicant` | P1 | 🟢 |
| A4 | Applicant profile Save refreshes, nothing persists | same `contactInfo` gap in self-profile | `updateSelfProfile` | P1 | 🟢 |
| A5 | Passport wrongly required to save profile | passport merged into required block | `ApplicantProfile.jsx` + `updateSelfProfile` | P1 | 🟢 |
